# 웹 우선 사용 흐름 설계 부록

요청: “skim은 기본으로 페이지를 열어서 해야 되고 웹 페이지에서 기능을 사용할 수 있어야 해 레포 연결도 할 수 있어야 해”.
이 문서는 [기본 설계](01-design.md)와 [현재 로컬 대시보드](04-web.md)를 확장하는 후속 구현 계획이다.
현재 CLI는 하위 명령을 요구하고 웹 설정은 조회만 지원한다. 이 PR은 문서만 추가하며 아래 기능의 구현 완료를 뜻하지 않는다.

## 진입과 화면

인자 없는 `skim`은 `skim web`과 동일하게 로컬 서버를 시작하고 브라우저를 연다.
이미 서버가 있으면 기존 사용자 전용 Unix 소켓으로 새 일회용 진입 URL을 발급받는다.
`skim web --no-browser`, `--port`, `--offline`과 기존 CLI 하위 명령은 유지한다.
브라우저 열기 실패 시 터미널의 URL로 진입하도록 안내한다. 서버 종료는 기존처럼 Ctrl+C로 한다.

웹에서 PR 탐색부터 저장소 연결·설정·수집·분석·상태 확인까지 수행한다.
최초 화면은 저장된 결과를 즉시 보여 주고, 데이터가 없으면 저장소 연결과 상태 점검으로 안내한다.

| 화면/행동 | 동작과 경계 |
| --- | --- |
| 저장소 연결 | 현재 `gh` 사용자가 접근할 수 있는 개인·조직 저장소를 페이지 단위로 조회하여 선택하게 한다. 기존 수집기의 소유·관리 권한 후보보다 넓은 접근 가능 목록이며, 자동 등록하지 않는다. `owner/repo` 직접 입력도 제공하고 읽기 접근을 확인한다. |
| 연결 해제 | 로컬 추적만 해제한다. 기존 CLI처럼 `repository` 출처를 제거하되 리뷰 요청 출처가 남은 PR·스냅샷·분석과 저장소 분석 정책은 보존한다. 연결 해제가 분석 동의 철회는 아님을 표시하고 별도 끄기를 제공한다. |
| 분석 동의 | 저장소별·조직별 LLM 분석 토글은 기본 꺼짐이다. 저장소 정책은 허용/거부/조직 설정 상속으로 구분하고 실제 적용값을 표시한다. 명시적 저장소 allow/deny가 조직 정책보다 우선하며, 조직 허용은 해당 조직 저장소 전체에 적용됨을 알린다. |
| 수집/새로고침 | 버튼으로 기존 정기 수집과 같은 작업 큐에 요청한다. 수집은 모델 전송 동의를 만들지 않으며, 수집 후 자동 분석도 기존 opt-in·예산·격리 검사를 따른다. |
| PR 분석 | 상세 화면에서 해당 PR의 최신 스냅샷 분석을 요청한다. 스냅샷이 없으면 먼저 수집하도록 안내한다. draft 수동 분석도 동일한 동의·예산을 따르고 이전 SHA 결과·미분석·차단·실패를 구별한다. |
| doctor/상태 | `gh` 인증, 조직 SSO·비공개 저장소·팀 접근, Codex 설치·전용 홈·격리 probe 유효성, 모델, 로컬 권한과 최근 작업을 보여 준다. 실패 항목마다 `gh auth login`, `skim codex-home init`, `skim doctor --probe` 등 기존 복구 절차를 안내한다. |
| 모델 설정 | `config.json`의 `codex_model`을 조회·저장한다. 기존 `valid_model` 검증을 사용하며 `unknown`·공백·선행 하이픈을 거부한다. `SKIM_CODEX_MODEL`이 우선하므로 파일값과 실제 적용값을 함께 표시한다. |

분석을 켜는 화면에는 **“허용하면 PR 코드·diff와 제목·설명이 Codex CLI를 통해 모델 서비스로 전송됩니다.
민감 정보 제외는 완전하지 않으며 서비스의 전송·보존 정책이 적용됩니다.”**를 표시하고 명시적으로 저장하게 한다.
연결·리뷰 요청 발견·분석 버튼 클릭만으로 동의를 켜지 않는다. 실행 직전에도 정책을 재확인한다.
조직 저장소는 분석 동의 여부와 무관하게 GitHub에 대해 항상 읽기 전용이며 리뷰 작성·수정·승인·머지 기능은 제공하지 않는다.

일반 doctor 실행은 실제 모델을 호출하지 않는다. 웹에서 자동으로 `--probe`를 실행하거나 인증·권한을 고치지 않는다.
모델 저장은 원자적으로 수행하고 다음 작업부터 설정을 다시 확정하여 적용하며 실행 중 작업의 모델은 바꾸지 않는다.
모델 변경 후 기존 probe가 새 모델과 맞지 않으면 분석을 차단하고 재검증을 안내한다. 캐시 키에는 기존처럼 모델을 포함한다.

## 요청·명령 실행 경계

- 서버는 계속 `127.0.0.1`에만 바인딩한다. 256비트 일회용 진입 토큰(60초, fragment 전달·즉시 제거)과
  서버 재시작 시 소멸하는 host-only `HttpOnly; SameSite=Strict` 세션 쿠키를 유지한다. 토큰·코드·CLI 원문은 로그에 남기지 않는다.
- 모든 변경은 POST만 허용한다. 연결/해제, 동의·모델 저장, 작업 등록을 GET에서 수행하지 않는다.
  GET은 저장 결과·설정·작업 상태 조회만 하며 페이지 방문이나 폴링으로 수집·doctor를 실행하거나 큐에 넣지 않는다.
- 세션별 난수 CSRF 토큰을 폼의 숨은 필드 또는 요청 헤더로 전달하고 상수 시간 비교한다.
  모든 요청의 `Host`는 실제 `127.0.0.1:<port>` 하나와 엄격히 대조한다. 변경 요청의 `Origin`은 정확한 서버 Origin 하나만 허용하고
  누락·중복·다른 Origin을 거부한다. 조회에도 Origin이 있으면 검사한다. 프록시 헤더를 신뢰하거나 CORS를 열지 않는다.
  세션 수립 POST는 아직 CSRF 토큰이 없으므로 일회용 진입 토큰과 Host·Origin 검사로 보호한다.
- 저장소 목록은 고정 명령 구조 `['gh', 'api', '--hostname', 'github.com', '--method', 'GET', ...]`로
  `user`, `user/repos`를 조회한다. 목록은 고정된 `affiliation=owner,organization_member,collaborator`와 페이지 매개변수를 사용한다.
  직접 입력 검증은 `repos/{owner}/{repo}` GET으로 한다. 메서드·호스트·엔드포인트 종류·플래그는 서버가 정하며 브라우저가 지정하지 못한다.
- 입력과 GitHub 응답의 `owner/repo` 모두 기존 검증과 같은 정규식
  `[A-Za-z0-9](?:[A-Za-z0-9-]*[A-Za-z0-9])?/[A-Za-z0-9_.-]+`로 전체 일치 검사하고 저장소 이름 `.`·`..`는 거부한다.
  조직명은 owner 부분만 허용한다. URL·임의 경로·추가 옵션은 받지 않는다. PR/스냅샷 ID도 DB 대상과 대조한다.
  모든 외부 실행은 argv 리스트만 사용하고 사용자 문자열을 셸에 전달하지 않으며 `shell=True`를 금지한다.
- 기존 CSP·이스케이프·인증된 diff 제공·0700/0600 권한을 유지한다. 본문 크기 제한(현재 4 KiB), 허용 필드·형식 검사,
  세션별 POST 빈도 제한과 전체 대기 작업 상한을 둔다. 과다 요청은 429와 재시도 안내를 반환한다.
  GitHub rate limit/Retry-After·지수 백오프와 기존 하루 20회 모델 호출 예산은 수동 요청으로 우회하지 못한다.

## 백그라운드 작업

HTTP 처리에서는 검증·설정 저장·작업 등록만 하고 오래 걸리는 외부 호출은 단일 워커에서 직렬 실행한다.
저장소 목록 갱신·직접 입력 접근 확인도 워커로 넘긴다. `collect`, `analyze`, `doctor`, 저장소 조회 각각 종류별로
대기 또는 실행 중인 작업을 최대 하나만 허용하며 중복 요청에는 기존 작업 ID를 반환한다.
다른 PR 분석이 이미 대기/실행 중이면 그 상태와 완료 후 재요청 안내를 표시하고 요청 대상을 조용히 바꾸지 않는다.
정기 수집도 같은 큐를 쓰고 실행 중 수집의 재갱신 요청은 기존 방식처럼 후속 1회로 합친다.

SQLite `jobs`를 확장해 대상·확정한 모델/입력 SHA, 대기/실행/완료/실패/보류 상태, 단계·처리 건수·전체 건수(알 때만),
시작/종료 시각·안전한 오류·재시도 가능 시각을 저장한다. 트랜잭션으로 점유하고 재시작 시 중단 작업을 복구한다.
인증된 읽기 전용 폴링 엔드포인트(예: `GET /jobs/{id}`)를 2초 간격으로 조회하고 완료 후 멈춘다.
분석 대기 중에도 기존 결과를 읽을 수 있고, 작업 취소는 이번 범위에 포함하지 않는다. `--offline`은 외부 호출을 하지 않는다.

## 후속 구현 PR

1. **A — 기본 웹 진입·설정/저장소 화면:** bare `skim` 별칭, 공통 CSRF/POST 검증 확장, 설정 저장과 동의·연결/해제 화면,
   접근 가능 저장소 선택/직접 입력을 구현한다. 기존 인증 경계를 재사용하고 목록 조회의 외부 호출은 워커로 처리한다.
2. **B — 작업 진행 표시:** collect/analyze/doctor를 공통 영속 작업 상태와 단일 워커로 통합하고 PR별 분석 요청·진행 폴링·오류/복구 안내를 연결한다.
   A의 저장소 조회 작업도 같은 상태 표시로 통합한다. 중복·예산·재시작·오프라인 동작을 검증한다.
3. **C — 사용 안내:** README의 기본 진입·연결·동의·점검 절차를 갱신하고 가짜 데이터 기반 화면 스크린샷을 추가한다.
   토큰·비공개 코드가 이미지에 포함되지 않게 한다.

## 열린 항목·미검증

- 조직 SSO·토큰 범위·팀 멤버십에 따른 실제 접근 가능 목록과 페이지 누락 여부는 실환경 검증이 필요하다.
  현재 소유/관리 후보 필터를 전체 접근 목록으로 재사용하지 않으며 조회 실패를 빈 목록으로 오인하지 않는다. GHE는 기존처럼 범위 밖이다.
- 작업 진행 필드·종류별 중복 제약의 DB 마이그레이션과 재시작 복구 세부 규칙, POST 빈도·큐 크기의 수치는 A/B에서 확정한다.
- HTTP 루프백의 Secure 쿠키 브라우저별 동작, 브라우저 열기 실패·재진입, 다른 로컬 포트에서의 CSRF 차단을 검증해야 한다.
- 실제 Codex 격리·인증 갱신과 평가 세트는 기존 미검증 상태를 유지한다. 웹 우선 전환으로
  [출시 체크리스트](release-checklist.md)의 차단 조건을 해제하지 않는다. 이 문서 PR에서는 실제 모델을 실행하지 않는다.
