# 웹 화면별 기능 정의

각 화면이 하나의 목적을 갖도록 정리한 기준이다. 버튼 위계는 화면당 주요 버튼(파랑 채움) 1개, 보조 버튼(연한 파랑), 위험 버튼(연한 빨강, 확인 단계 필수)으로 나눈다.

| 화면 | 목적 | 주요 행동 | 보조 행동 |
|---|---|---|---|
| `/` PR 리뷰 | 관리(연결)하는 저장소의 PR에서 먼저 볼 파일을 찾는다 | 카드의 '먼저 볼 파일'(상위 3개)을 눌러 해당 변경으로 이동 | 수치 탭(전체·리뷰 요청·높음 파일 있음·분석 전), 검색·저장소 선택, 지금 수집 |
| `/pr/<id>` PR 상세 | 한 PR의 변경과 분석 근거를 읽는다 | 우선순위 순으로 변경 읽기 | 이 PR 분석, 저장소 분석 설정 열기, 원래 파일 순서·전체 diff 보기, GitHub 원문 |
| `/repos` 저장소 | 호스트별로 연결한 저장소와 분석 허용 범위를 한 목록에서 관리한다 | 범위(안 함·모든 저장소·선택) 고르고 저장소 체크 → 저장 | 호스트 탭, 카드 안 `+ 저장소 추가`(불러오기, 주소로 연결은 접힘, 연결 즉시 목록 맨 위에 '연결 확인 중' 행), 연결 해제(확인), 호스트 관리 |
| `/status` 상태 | 지금 문제가 있는지와 작업 결과를 확인한다 | 상태 점검 실행 → 점검 결과(실패·경고 먼저, 항목별 복구 안내) | 작업 기록 한 목록(진행 중 먼저, 실패 이유 바로 표시), 지금 수집, Codex 분석 준비(문제 있을 때만 펼침), 복구 안내 |
| `/settings` 설정 | 분석 모델을 정한다 | 모델 저장 | 분석 허용 범위로 이동 |

## 의도적으로 두 곳에 있는 기능
- **지금 수집**: `/`는 리뷰 흐름의 빠른 진입점, `/status`는 운영 맥락. 둘 다 같은 작업을 만든다.
- **팀**: 메인에는 두지 않는다. 팀 저장소는 `/repos`의 `내 팀 저장소` 조회로 찾아 연결하고, 메인은 연결한 저장소만 보여준다.
- **분석 허용**: `/repos`의 분석 허용 범위 한 곳에서만 정한다(GitHub 앱 설치처럼 호스트별 안 함·모든 저장소·선택한 저장소만).

## 흐름 원칙
- 메인 카드의 파일 중요도는 그 파일 변경 단위 중 가장 높은 값이다. 높음·보통과 규칙 후보 파일만 최대 3개 보여주고, 낮음·미분석은 개수와 분포 막대로만 보여준다. 다른 저장소의 리뷰 요청 PR은 메인에 나오지 않는다.
- 분석 허용(동의)과 분석 요청은 분리한다. PR 상세에서 허용이 필요하면 `/repos?scope_host=<호스트>&select_q=<저장소>&from_pr=<id>#analysis-scope`로 이동하고, 저장 후 같은 화면의 안내에서 PR로 돌아간다. 돌아갈 주소는 숫자 PR 번호로만 만든다.
- 동의 체크는 저장 버튼보다 앞에 둔다. 서버는 `confirm=yes`를 계속 검사한다.
- 연결 해제·호스트 삭제는 펼쳐서 영향을 읽은 뒤에만 확인 버튼이 보인다(스크립트 없이 `<details>`).
- 빈 화면은 원인을 구분한다: 조건에 맞는 PR 없음 → 필터 초기화, 수집된 PR 없음 → 저장소 연결·상태 확인.
- 상태 값은 화면에만 한국어 표시명을 쓰고(높음·보통·낮음, 분석 완료 등) 쿼리 값과 CSS 클래스는 영문을 유지한다.

## 남은 검토 항목 (Codex 검토 중 이번에 하지 않은 것)
- PR 상세에서 목록으로 돌아갈 때 필터·검색·페이지 유지
- 저장 성공 알림과 오류를 필드 옆에 표시(현재는 공통 오류 페이지)
- 작업 완료 후 종류별 다음 행동 버튼(조회 결과 보기, PR 목록 보기 등)
