# Skim 릴리스 전 검토 — 2026-11-04

## 범위와 판정

2026-11-04에 로컬 작업 트리의 분석, 설치·업데이트, PR 상세 및 릴리스 게이트를 코드와 설계 문서로 검토했다. **정식 릴리스는 보류한다.** 이 문서는 당시 미커밋 변경 사항까지 포함한 스냅샷을 기록한다. 그중 분석 프롬프트 `skim-ko-6`, 새 중요도 정책과 함수 탐색은 이 문서를 포함하는 PR의 기준 커밋에 아직 반영되지 않았다. 아래 결과를 해당 기능이 이미 배포되었다는 뜻으로 해석하지 않는다.

## 출시 차단

1. **실제 분석 품질 평가 미완료.** 당시 작업 트리의 `skim-ko-6`에는 사람의 정답 확인과 실제 모델 결과가 없었다. 출시 검사 실행도 `eval/skim-ko-6/manifest.json` 누락으로 실패했다. 같은 모델과 CLI, 확인된 정답으로 반복 평가하고 사람이 결과를 검토해야 한다. `docs/release-checklist.md`, `.design/pr-context-accuracy/GATES.md`의 G8을 참고한다.
2. **설치 자산 생성 불가.** `lib/skim/release_package.py`는 `lib/skim/bootstrap.py`를 요구하지만 파일이 없다. 최초 설치 bootstrap과 영구 launcher를 완성하고 설치 경로를 검증해야 한다.
3. **정식 업데이트 미완성.** `skim update`는 릴리스 조회만 가능하다. CLI·웹 적용, 작업 종료 대기, 버전 전환, 서버 readiness 및 장애 복구를 연결해야 한다. 설치·업데이트 설계의 완료 게이트 8개가 미충족이었다. `.design/install-update/PLAN.md`와 `GATES.md`를 참고한다.
4. **후보 커밋 미고정.** 당시 로컬에는 다수의 미커밋 변경이 있었다. 원격 main의 성공한 CI는 그 변경을 포함하지 않는다. 릴리스에 포함할 변경을 확정한 뒤 해당 커밋의 CI와 출시 게이트를 확인해야 한다.

## 보완 사항

- 당시 새 중요도 정책은 테스트 중심 PR, 검증 약화, 대응 테스트, fixture, 핵심 UI, 정보 부족에 대한 평가를 요구했지만 자동 출시 검사는 해당 시나리오를 필수로 강제하지 않았다. 모델의 중요도 판정과 규칙 후보 포착을 구분해 품질을 확인할 필요가 있다.
- 당시 함수 탐색은 `get`, `find`, `add` 등과 이름이 같은 프로젝트 메서드 호출도 제외할 수 있었다. 표준 라이브러리 오탐을 줄이면서 프로젝트 함수의 사용 위치를 찾을 방법이 필요하다.
- PR 맥락 정확도 G5의 기존 검증은 동일 버전 입력의 캐시 동작만 확인하므로 구버전 캐시·출시 증거 분리의 근거로는 부족하다.
- 당시 함수 탐색 설계 문서의 단일 후보 동작 설명이 실제 UI와 달랐다.

## 검증과 한계

- 당시 `python3 scripts/check_release.py`: 실패. `skim-ko-6` manifest 누락.
- 당시 `python3 -m compileall -q lib scripts`, `node --check lib/skim/web_static/jobs.js`, `git diff --check`: 통과.
- 단위·통합 테스트, 실제 브라우저, 설치·업데이트 실행, 실제 모델 평가는 그 검토에서 실행하지 않았다. 구문 검사와 코드 읽기는 이 검증들을 대신하지 않는다.
- 분석 잠금과 자동·수동 예산 분리, 정제 및 ID 검사 경로를 코드로 확인했지만 프로세스 강제 종료나 실제 모델 응답의 동작을 검증한 것은 아니다.
