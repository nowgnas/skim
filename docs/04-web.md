# 로컬 대시보드

기본 진입과 웹 기능 확장 계획은 [웹 우선 사용 흐름 설계 부록](05-web-first.md)을 참조한다.

`bin/skim web`은 127.0.0.1의 임의 포트에서 실행하며 브라우저를 연다.
고정 포트는 `--port 8765`, URL만 출력하려면 `--no-browser`를 사용한다.
실행 중 다시 `skim web`을 호출하면 사용자 전용 Unix 소켓으로 새 URL만 발급한다.
종료는 서버를 실행한 터미널에서 Ctrl+C를 누른다.

진입 URL의 fragment 토큰은 60초 동안 한 번만 사용할 수 있다. 진입 스크립트가
주소에서 먼저 지운 뒤 동일 Origin으로 교환한다. 세션은 서버 재시작 시 소멸하며
HttpOnly·SameSite=Strict·host-only 쿠키로 유지한다. HTTP 루프백의 Secure 쿠키
처리는 브라우저별 차이가 있으므로 이 구현은 Secure를 설정하지 않는다. 브라우저별
Secure 동작 검증은 수행하지 않았다. 다른 포트도 쿠키를 받을 수 있으므로
모든 변경 요청에서 정확한 Origin 및 별도 CSRF 토큰 검사를 강제한다.
URL을 공유하지 않으며, 초기 진입 셸에는 PR 데이터를 포함하지 않는다.

목록에서 저장소·리뷰 요청·중요도·분석 상태를 필터링할 수 있다. 상세에서는
규칙 후보·미분석·high를 펼치고 나머지를 접는다. 파일명·라인 범위·정제된 hunk와
판정 근거를 확인하고, 전체 원본 diff 또는 GitHub 변경 화면으로 이동할 수 있다.
이전 SHA 결과, 분석 실패·차단·부분 분석, 수집 오류를 별도로 표시한다.
원본 diff에는 분석에서 제외한 민감 정보가 있을 수 있으므로 인증 후에만 표시한다.
Sessio 인덱스에서 저장소·브랜치 후보가 정확히 하나이며 현재 gh 사용자와
PR 작성자가 일치할 때 상세 화면에 세션 링크·ID를 표시한다. 경로와 로컬
웹 주소는 `sessio_index_path`, `sessio_web_url` 설정으로 지정한다.
`--offline`에서는 Sessio 사용자 조회와 링크 표시를 생략한다.

목록·상태 화면의 수집 버튼, 상세 화면의 PR 분석 버튼(분석 허용 저장소만), 상태 화면의
점검 버튼은 SQLite 작업 큐에 등록만 한다. 내장 단일 워커가 설정된 간격의 정기 수집과
함께 종류별 하나씩 직렬 실행하며 수집 후 허용된 최신 스냅샷을 분석한다. 진행 상태는
2초 간격으로 폴링해 표시한다. Codex 격리 계약이 확인되지 않으면 기존 분석기의 차단
정책을 유지한다. 세부 규칙은 [웹 우선 설계 부록](05-web-first.md)의 PR B 절을 참조한다.

## 외부 통신 없는 데모

```bash
python3 scripts/demo_seed.py --home /tmp/skim-demo
SKIM_HOME=/tmp/skim-demo bin/skim web --offline
```

데모 스크립트는 비어 있는 전용 SKIM_HOME에서만 동작한다. 가짜 모델 응답으로
high·mid·low, 민감 경로 제외, 분석 대기, 이전 SHA 사례를 만든다.
`--offline`에서는 워커를 실행하지 않으며 수집·분석·점검 요청을 거부하고 큐에 남기지 않는다.

HTTP 보안 테스트는 메모리 속 연결로 요청을 재현하며 실제 소켓·GitHub·LLM을
호출하지 않는다. 실행: `python3 -m unittest discover -s tests`.
