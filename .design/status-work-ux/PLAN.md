# 상태와 작업 화면 가독성 및 진행 표시

> 상태: 완료 · 기준 커밋: `20e8de7` · 규모: 표준 · 고위험: 아니오

## 1. 요구사항
- 상태 점검, 수집, 활성 작업, 최근 작업, 복구 안내 영역을 명확하게 구분한다.
- 시간이 걸리는 작업의 대기 및 실행 상태를 즉시 알아볼 수 있게 한다.
- 작업 진행률을 알 수 있으면 실제 처리 건수를 표시하고, 알 수 없으면 대기 또는 진행 중 표시를 사용한다.
- 작업 완료, 실패 및 복구 안내를 기존대로 확인할 수 있고 모바일에서도 사용할 수 있다.

## 2. 정책 점검
- ✅ 작업 등록, 직렬 큐, 중복 요청 및 기존 결과 처리는 유지한다.
- ✅ 작업 정보는 기존 `/jobs/{id}` 폴링으로 갱신한다. 진행률은 제공되는 processed/total에 한한다.
- ⚠️ 진행 중 표시는 화면 전반의 기존 작업 상자에 적용해 상태 점검·수집·분석·저장소 조회에 일관되게 보여준다.
- ⚠️ 복구 안내는 별도 접을 수 있는 영역으로 분리한다. 활성 작업과 최근 작업은 구분된 카드로 표시한다.

## 3. 열린 질문
- 없음. 위 가정과 설계에 대한 승인 필요.

## 4. 코드 맥락
- `lib/skim/web_jobs.py`: 상태 화면과 작업 상자 생성.
- `lib/skim/web_static/jobs.js`: 활성 작업의 폴링과 완료 후 새로고침.
- `lib/skim/jobs.py`: 대기·실행 상태 및 processed/total 제공.
- `lib/skim/web_static/app.css`: 화면 테마, 반응형 스타일, 모션 감소 설정.
- `tests/test_web_jobs.py`, `tests/test_web.py`: 작업 표시와 HTTP 동작 검증.

## 5. 설계
- 상태 점검과 수집을 별도 카드로 배치하고 활성 작업, 최근 작업 및 복구 안내를 독립된 섹션으로 나눈다. 좁은 화면은 한 열로 배치한다.
- 작업 대기는 '대기 중', 실행은 '작업 중'과 움직이는 표시로 구분한다. 실제 총량이 있는 작업은 진행률을 표시하고, 그 외는 불확정 상태를 보여준다.
- 작업 상자를 기존 polling 응답으로 갱신하고 완료 시 기존처럼 새로고침한다. 폴링 실패도 기존 자동 재시도 안내를 유지한다.
- 스크린 리더 상태 안내와 모션 감소 설정을 지원한다. 서버, 데이터 및 작업 API 계약은 바꾸지 않는다.

## 6. 검증 계획
- 대기·실행·완료 작업의 표시와 실제 진행률, 알 수 없는 진행률, 폴링 결과 갱신, 오프라인 상태를 검증한다.
- 기존 웹 작업 및 전체 테스트와 `git diff --check`를 실행한다.
- 가능한 경우 브라우저에서 넓은 화면과 좁은 화면을 직접 확인한다.
