# Codex 버전 차단 안내와 작업 화면 움직임

> 작성일: 2026-11-02 · 기준: 현재 main 및 기존 미커밋 웹 초기화 변경 · 고위험: 검토 필요 — CLI 실행 경로와 격리 경계

## 증상·재현
- 실행 중 skim의 PATH에서 선택한 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex --version`은 `codex-cli 0.166.0-alpha.5.1`을 반환한다.
- `CodexAdapter.check_version()`은 안정 버전 숫자 형식만 허용해 이를 차단한다. `flags`와 `probe`는 선행 실패로 실행되지 않는다.
- 작업 진행·완료 시 상태 문구, 진행 표시, 작업 목록 및 전체 reload로 카드 높이와 위치가 달라진다. 사용자는 상태 점검·작업 진행 중을 지목했다.
- 프로젝트 프론트엔드는 서버 렌더링 HTML과 자체 CSS·순수 JavaScript이다.

## 원인
- `lib/skim/analyze/codex.py:132`: 안정 버전만 허용하도록 의도된 정규식. alpha 거부를 없애면 검증된 보안 경계가 바뀐다.
- `lib/skim/doctor.py:49`: version 실패 뒤 flags·probe 검사를 건너뛰지만 화면 문구는 최초 원인을 충분히 구분하지 못한다.
- `lib/skim/web_static/jobs.js`: 작업 종료 시 전체 새로고침. `lib/skim/web_jobs.py`, `web_static/app.css`: 작업 상태에 따라 높이가 변한다.

## 수정 방향 초안
- 안정 버전 제한과 기존 격리 검증을 유지한다. 현재 감지한 CLI의 버전과 안정 버전 필요 사유, 설치 및 재시작 방법을 화면에 분명히 표시한다.
- 안정 Codex CLI를 `~/.local/share/skim-tools`에 별도 설치하고, skim을 실행할 때만 그 `node_modules/.bin`을 PATH 맨 앞에 둔다. 앱 내 CLI나 다른 설정은 바꾸지 않는다. 현재 실행 중인 skim은 종료 및 해당 환경으로 재시작이 필요하다.
- 실행 파일 선택 로직과 probe 캐시의 보안 계약은 변경하지 않는다. 설치된 CLI도 기존 안정 버전·플래그·probe 검사를 모두 통과해야 한다. 설치 실패나 추가 검사 실패는 사용자에게 표시한다.
- 공식 npm 패키지를 별도 경로에 설치한다.
- 상태 점검·작업 카드에 일관된 배치와 진행/완료 정보 영역을 마련하고, 작업 완료 시 자동 전체 reload를 하지 않고 기존 카드 안에 최종 상태와 결과를 표시한다. 목록 재정렬은 사용자가 새로고침할 때 하며, 긴 결과는 명시적으로 펼쳐 확인한다.
- 기존 미커밋 웹 초기화 변경을 보존한다. 기능 삭제, 보안 검사 완화, 인증정보 노출은 하지 않는다.

## 검증 계획
- alpha 버전 거부 및 구체적 진단, 안정 버전의 기존 검사와 선택된 실행 환경을 가짜 CLI로 검증한다. 실제 계정의 probe나 모델 호출은 하지 않는다.
- 작업 대기→진행→완료·실패 시 화면의 위치 및 입력·스크롤 보존을 브라우저와 테스트로 확인한다.
- 영향 테스트·전체 unittest·독립 보안 리뷰를 수행한다.

## 결과
- 안정 CLI 0.166.0을 별도 경로에 설치하고 version 및 flags 검사를 확인했다. 실제 probe는 실행하지 않았다.
- alpha 감지와 설치·PATH·재시작 안내, 자동 새로고침 제거, 결과 표시와 고정된 요약 영역을 구현했다.
- 전체 unittest 262개 통과. 브라우저 모의 화면에서 실패 전후 다음 섹션 좌표가 같음을 확인했다. 좁은 화면의 실제 브라우저 측정은 하지 못했다.
- 독립 리뷰의 설치 안내와 좁은 화면 요약 높이 지적을 반영했다.
- 기존 서버를 종료한 뒤 재시작 명령은 guard-prod-ops 훅에 차단되었다. 수집 작업은 재시도 대기 상태로 DB에 남아 있다.
