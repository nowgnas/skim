# 메인 팀 저장소 필터와 Codex 실행 경로

> 상태: 승인됨 · 기준 커밋: `0fd57ed` 및 기존 미커밋 작업 · 규모: 표준 · 고위험: 아니오

## 1. 요구사항
- 메인 PR 목록에서 호스트와 소속 팀을 선택해 그 팀의 저장소에 속한 PR만 본다. 기존 저장소·중요도·상태·검색과 조합할 수 있다.
- 매번 긴 PATH 지정 없이 `skim web`으로 실행할 때 별도 설치한 안정 Codex를 사용할 수 있다.

## 2. 정책 점검
- GitHub 조회는 기존 호스트 등록, 소속 확인, SSO 및 백그라운드 작업 경계를 유지한다.
- 조회 결과가 아직 없거나 실패·부분 조회인 경우 전체 결과로 오인하지 않도록 상태를 표시한다. 팀 저장소를 조회해도 연결·분석 허용은 변경하지 않는다.
- 팀과 저장소의 관계는 현재 메모리 캐시이므로 재시작 뒤에는 새 조회가 필요하다. 빈 결과와 미조회는 구분한다.
- 기존 안정 버전·격리·probe 검사를 유지한다. 실행 경로 선택 변경은 검사 우회를 허용하지 않는다.

## 3. 코드 맥락
- `lib/skim/web.py`: 메인 필터와 검색, CSRF 보호 POST.
- `lib/skim/web_settings.py`, `jobs.py`: 호스트·팀 조회, 작업 큐, 기존 결과 캐시.
- `bin/skim`, `lib/skim/analyze/codex.py`, `doctor.py`: 실행 환경과 Codex 검사.
- 기존 미커밋 변경을 보존한다.

## 4. 설계
- 메인에서 기존 조회 작업을 이용해 호스트별 소속 팀을 불러오고, 선택한 팀의 저장소 조회가 끝나면 해당 호스트 및 저장소와 일치하는 PR만 필터링한다. 기존 검색과 필터를 보존하고 팀 조회 시 페이지는 첫 페이지로 초기화한다. 작업 중·실패·부분 결과를 명시한다.
- 팀별 조회가 완료되기 전에는 선택한 팀에 대한 필터 결과로 가장하지 않는다. 결과는 같은 호스트와 선택 팀의 완료된 캐시에서만 사용한다.
- `bin/skim`에서 `~/.local/share/skim-tools/node_modules/.bin/codex`가 실행 가능할 때 해당 디렉터리를 PATH 앞에 추가한다. 없으면 기존 PATH를 사용한다. 추가 환경변수 설정이나 다른 프로그램의 설치는 하지 않는다. Codex 검증과 격리 환경은 유지한다.
- 기존 설치 안내와 실제 동작이 일치하도록 문서를 수정한다.

## 5. 확인 계획
- 팀·호스트·기존 필터 조합, 빈 결과, 부분/실패 결과, 수집 작업 상태 및 캐시 변경을 확인한다.
- 실행 경로 자동 선택 및 없을 때 대체, Codex의 기존 검사를 확인한다. 테스트 추가나 실행은 사용자 요청이 없으므로 하지 않는다.
- 변경 diff·구문 확인 및 독립 리뷰를 수행하고 실행하지 못한 확인을 보고한다.

## 7. 결과
- 메인에서 소속 팀을 불러와 선택하고 해당 팀 조회의 완료된 결과로만 PR을 필터링한다. 오류, 조회 중, 부분 결과를 표시한다.
- 실행 스크립트가 별도 설치된 Codex 경로를 자동 선택한다. 설치되지 않았으면 기존 PATH를 사용한다.
- 독립 리뷰의 동시 조회 충돌과 오래된 결과 표시 지적을 반영했으며 2차 정적 리뷰에서 미해결 지적은 없었다.
- `git diff --check`와 Python AST 구문 확인을 수행했다. 테스트 및 실제 브라우저·GitHub 조회는 실행하지 않았다. `bash -n bin/skim`은 guard-prod-ops 훅이 차단했다.
