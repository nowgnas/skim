# 저장소 관리 흐름과 PR 상세 개선

> 상태: 승인됨 · 기준 커밋: `0fd57ed` 및 기존 미커밋 변경 · 규모: 표준 · 고위험: 아니오

## 1. 요구사항과 성공 기준
- 저장소를 찾고 연결 상태와 분석 허용 상태를 확인·변경하는 흐름을 한 화면에서 제공한다.
- 저장소 조회에서 호스트와 팀을 선택하고 해당 조건을 결과에 명확히 표시한다.
- PR 상세에서 변경 의도·중요한 검토 지점·수집/분석 상태·작업을 시각적으로 구별한다.
- 기존 검색, 페이지, 호스트, 수집, 분석 동의, 조직 정책 및 미커밋 작업을 보존한다.

## 2. 정책 점검
- ✅ GitHub 저장소와 팀 조회는 기존 등록 호스트에 대한 읽기 전용 API, SSO 검증 및 호출 제한을 따른다.
- ✅ 분석 허용은 사용자의 명시적인 모델 서비스 전송 확인을 유지한다. 조직 정책 상속과 저장소 우선순위도 유지한다.
- ✅ GitHub 조회만으로 저장소 등록이나 분석 허용을 변경하지 않는다.
- ✅ 사용자가 소속 팀을 개별 선택해 해당 팀 저장소를 조회한다.

## 3. 열린 질문
- 없음. 개별 소속 팀 선택을 사용자에게 확인했다.

## 4. 코드 맥락
- `lib/skim/web_settings.py`: 호스트/팀 조회, 저장소 연결, 모델 및 정책 화면과 동의 검증.
- `lib/skim/jobs.py`: 저장소 조회 작업 큐와 파라미터.
- `lib/skim/web.py`: PR 상세, 결과·변경 단위 렌더링 및 POST 복귀.
- `lib/skim/web_jobs.py`: PR 분석 요청 상태와 실행.
- `lib/skim/web_static/app.css`: 기존 화면과 diff·모바일 스타일.
- `lib/skim/db.py`, `lib/skim/repos.py`: 저장소 정책·조직 상속과 연결 동작.

## 5. 설계
- 저장소 페이지를 관리 진입점으로 삼고 조회 결과에 연결 및 실제 분석 허용 상태를 표시한다. 연결된 저장소의 정책 제어를 같은 화면에서 제공하고 명시적 동의를 유지한다.
- 현재 설정 화면의 저장소별 중복 목록은 제거하거나 관리 화면 링크로 대체한다. 모델 설정과 조직 단위 정책은 유지한다.
- 기존 API·캐시·큐·등록 호스트 검증을 재사용한다. 개별 팀 선택이 필요하면 팀 식별자 검증, 호스트별 조회·캐시 분리, 실패 시 이전 결과 보존 및 제한을 유지한다.
- PR 상세는 의도와 검토 포인트를 먼저 보여주고 수집·분석 상태와 실행 조작을 별도 보조 영역으로 구분한다. 위험 라벨과 diff의 기존 의미는 유지한다.
- 새 프레임워크나 데이터베이스 스키마를 도입하지 않는다. 기존 동의·재시도·권한 정책을 변경하지 않는다.

## 6. 확인 계획
- 팀 및 호스트 조합, 검색·페이지·연결 상태, 조직 상속과 명시적 동의, 오류와 빈 결과, 상세의 미분석·부분 분석·위험 항목과 작은 화면을 확인한다.
- 사용자 요청이 없는 테스트 추가·실행은 하지 않는다. 정적 diff 및 구문 확인, 독립 리뷰를 수행하고 실제 브라우저 확인 가능 여부를 보고한다.

## 8. 대안 · 결정 이력
- 사용자 화면에서 관리 진입점을 통합하되 기존 정책 저장과 동의 검증을 재사용한다.

## 9. 결과
- 저장소 화면에서 조회·연결·정책 관리를 제공하고 설정의 중복 저장소 정책 목록을 링크로 대체했다.
- 소속 팀 목록에서 개별 팀을 선택해 해당 팀만 조회한다. 선택 팀을 작업에 전달하며 호스트·모드·팀을 캐시 판별에 포함한다. 소속 검증과 기존 조회 한도·실패 보존 정책을 유지한다.
- PR 상세의 의도·검토 포인트, 수집·분석 상태 및 분석 요청을 구분했다.
- 독립 리뷰 1차의 팀 조회 한도와 관리 링크 지적을 반영했고 2차 정적 리뷰에 남은 지적은 없었다.
- `git diff --check`, Python AST 구문 확인을 수행했다. 테스트와 실제 브라우저·GitHub API 실행은 하지 않았다.
