# 열린 이슈 개선

## 범위
- #63 보관 기간 설정이 자동 정리에 적용되지 않음을 설정과 문서에서 표시한다. 기존 데이터는 자동 삭제하지 않는다.
- #64 동일 SHA·제목·본문과 완전한 스냅샷 및 검증된 캐시가 있으면 파일과 diff 재요청을 생략한다. PR 조회 ETag와 저장소 후보 24시간 프로세스 내 캐시를 사용한다. 메타데이터 변경, 누락·손상 및 불완전 수집 시 기존 전체 수집을 유지한다.
- #65 공개 저장소 상태와 현재 설치·업데이트의 gh 인증 요구를 구분해 안내한다.
- #66 격리 probe 기록에 활성 기능 목록을 고정하고 변경 시 재검증한다.
- #67 태그 출시 게이트와 Python·JS 정적 구문 검사를 CI에 연결한다.
- #68 특정 사용량 설정의 숫자·불리언 리터럴만 가림에서 제외한다. 인증 값과 문자열은 계속 가린다.
- #69 에러의 고정 화면 문구를 유지하며 예외 유형과 분석 단계만 비밀값 없는 소유자 전용 로컬 로그에 기록한다.

## 경계
- 추적 저장소·PR의 기존 데이터, 스냅샷과 수집 실패 보존 규칙을 유지한다. 보관 기간 자동 삭제는 이슈의 임시 안내 대안을 적용한다.
- 새 probe 기록이 없는 기존 설치는 재검증이 필요하다. 민감 정보 판정의 캐시 정책은 별도 버전으로 분리한다.
- ETag는 호스트·엔드포인트별 메모리에서만 유지하고 검증된 304 응답에만 이전 응답을 재사용한다. 저장소 후보 캐시는 호스트·로그인별 성공 결과만 최대 24시간 사용하며 프로세스 종료 시 사라진다. 권한 변화가 즉시 목록에 반영되지 않을 수 있다.
- 사용자 요청에 자동 테스트가 포함되지 않아 테스트를 추가하거나 실행하지 않는다. Python·JS 구문, 릴리스 검사 및 diff 공백을 확인하고 미검증 범위를 보고한다.

## 결과와 남은 검증
- #63은 자동 삭제 대신 미적용 상태를 설정 화면과 문서에 표시하고 신규 설정 기본 파일에서 해당 키를 제외했다. 기존 설정과 데이터는 보존한다.
- #64는 조건부 PR 조회와 프로세스 내 24시간 후보 캐시, 정상 스냅샷·파일 해시 확인 후 diff 재사용을 적용했다. 캐시가 만료되거나 프로세스가 재시작하면 다시 조회한다.
- #65~#69는 공개 저장소 안내, probe 기능 목록 일치 확인, CI 정적 검사·태그 게이트, 사용량 설정 정제 예외, 내용 없는 진단 로그를 적용했다.
- 정제 정책을 `redact-v3`으로 구분하고 평가 결과의 정책을 검사한다. 기존 결과는 정책 정보가 없어 실제 모델 재평가와 사람 검토 전까지 출시가 차단된다.
- 독립 리뷰: 기존 테스트 fixture의 정책 필드와 재수집 전제를 수정했다. 신규 ETag·캐시, 정제·probe 및 로그 보안 경계에 대한 회귀 검증과 기존 테스트 실행은 하지 않았으며 미완료다.
- Python `compileall`·`tabnanny`, JavaScript 구문, workflow YAML 파싱과 `git diff --check`를 확인했다. `scripts/check_release.py`는 의도대로 정제 정책 평가 불일치로 실패했다.
