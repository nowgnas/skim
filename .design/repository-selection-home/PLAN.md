# 저장소 선택과 홈 화면 개선

> 상태: 승인됨 · 기준 커밋: `0fd57ed` 및 기존 미커밋 변경 · 규모: 표준 · 고위험: 아니오

## 1. 요구사항
- 저장소 선택에서 내 팀 저장소와 사용자가 말한 도메인을 쉽게 선택한다.
- 둥근 사각형 안에 코드 라인과 리뷰를 표현한 로고를 표시한다.
- 홈 화면의 제목과 설명, 검색·필터·PR 목록의 구분을 개선한다.
- 기존 연결, 검색, 페이지 이동, 분석 허용 및 보안 정책을 유지한다.

## 2. 정책 점검
- ✅ 내 팀 조회는 기존 GitHub 읽기 전용 API와 요청 제한을 사용한다. `lib/skim/web_settings.py:102`
- ✅ 기존 저장소 연결·분석 동의는 변경하지 않는다.
- ✅ 도메인은 GitHub 호스트를 의미한다. 사용자 확인.

## 3. 열린 질문
- 없음. GitHub 호스트를 선택 기준으로 사용한다.

## 4. 코드 맥락
- `lib/skim/web_settings.py`: 호스트·팀 범위별 저장소 조회와 검색·페이지.
- `lib/skim/web.py`: 홈 PR 목록, 공통 헤더와 SVG 로고.
- `lib/skim/web_static/app.css`: 공통 및 반응형 스타일.
- `tests/test_web_settings.py`, `tests/test_web.py`: 기존 동작 계약.
- 기존 작업 중인 미커밋 변경을 보존한다.

## 5. 설계
- 이미 구현된 전체/팀 조회 기능을 재사용하고 검색 결과와 조회 조건을 이해하기 쉽게 배치한다. 검색과 페이지 이동 및 연결 후 선택 상태 보존을 고려한다.
- 도메인은 확인된 기준의 기존 데이터로만 필터한다. 새 분류 체계나 외부 의존성은 임의로 도입하지 않는다.
- SVG와 CSS로 로고를 제작하고 홈 제목을 `PR 리뷰`로 변경하여 기능 설명, 필터, 결과 목록을 구분한다. 작은 화면에서도 내용과 조작을 사용할 수 있게 한다.
- 스키마 변경 없음. GET 목록 필터를 추가하면 쿼리 검증과 POST 후 목록 상태 보존을 함께 수정한다.
- GitHub 조회, 호스트 인증과 작업 큐의 기존 실패·동시성 정책을 유지한다.

## 6. 검증 계획
- 사용자 요청에 따라 구현 결과를 코드 diff와 필요한 화면 확인으로 살핀다. 별도 테스트 추가나 실행은 요청되지 않았다.
- 팀/호스트 및 도메인 조합, 빈 결과, 검색과 페이지, 연결 후 선택 상태, 모바일 레이아웃을 확인 대상으로 삼는다.

## 9. 결과
- 기존 팀 조회와 호스트 선택을 저장소 화면 상단에 배치하고 연결·호스트 관리를 구분했다.
- 코드 라인과 체크 모양의 로고, PR 리뷰 설명과 목록 영역을 적용했다.
- 기존 검색 폼 테스트가 화면 순서에 의존하던 선택자를 필드 이름 기준으로 수정했다.
- `git diff --check` 및 Python AST 구문 확인 통과. 테스트와 브라우저 측정은 실행하지 않았다.
- 독립 리뷰: 분석 정책 안내와 검색 폼 선택자를 수정했다. 중간 화면에서 폼이 넘칠 가능성에 대비해 800px 이하에서 flex로 전환했다. 실제 브라우저 폭 측정은 미실시다.
