# PR 목적과 핵심 파일 선정 개선

## 요청과 결정

- PR 목적과 핵심 파일 선정의 정확도를 높인다. 사용자는 다중 청크 PR에서 모델 호출·시간 증가를 허용했다.
- 사용자 최신 요청: 주기적 자동 분석에는 하루 20회 호출 한도를 적용하고, PR 화면과 터미널에서 사용자가 직접 요청한 분석에는 일일 호출 횟수 제한을 적용하지 않는다. 수동 호출은 자동 예산을 소모하지 않는다. 분석 허용·격리·동시 실행 잠금과 호출별 재시도 상한은 유지한다.
- 사용자는 메인의 ‘먼저 볼 파일’에 중요도와 PR 목적 관련성을 함께 반영하기로 선택했다. 중요도를 먼저 적용하고 같은 등급에서는 검증된 목적 관련성 순서를 사용한다.
- 실제 정확도 향상은 평가 전 가정이다. 미확인 파일을 안전하다고 판단하거나 미분석을 감추지 않는다.

## 현재 동작

- PR 제목·설명과 정제된 변경을 최대 200 KiB·100단위 청크로 나누어 순서대로 평가한 뒤 결과를 합성한다. 각 청크는 다른 청크의 실제 변경을 볼 수 없다.
- 원본 diff 1 MiB, 200파일, 500단위 등 기존 제한이 있으며 제외·정제·누락 사유를 기록한다. 하루 20회에는 청크·합성·재시도가 포함된다.
- `skim-ko-4`의 실제 모델 출시는 전체 평가 및 사람 검토가 없어 차단 중이다. 기존 작업 트리와 사용 중인 앱이 있다.

## 설계 초안

1. 단일 청크는 추가 개요 호출 없이 현재 흐름을 사용한다.
2. 여러 청크는 기존 민감 경로 제외·정제가 끝난 입력에서만 파일별 균형 잡힌 제한 크기 발췌와 변경 범위 정보를 구성하고 누락 여부를 기록한다. 파일마다 원래 순서와 정해진 UTF-8 바이트 한도를 적용하고, 전체 발췌가 한도를 넘으면 일부만 포함했다는 수치와 사유를 붙인다. 실제 diff 일부만 보았음을 명시하며, 원본 비밀값과 제외 경로는 전송하지 않는다.
3. 제한된 입력으로 PR 목적·변경 축의 개요를 모델 호출 1회로 생성한다. 개요는 증거가 아닌 참고 자료이며, 해당 청크의 diff로 확인되지 않는 내용을 사실이나 중요도 근거로 사용하지 못하게 한다. 프롬프트 주입 방어와 출력 정제, 엄격한 크기·형식 및 입력 ID 검증을 적용한다.
4. 개요를 각 청크에 제공해 기존 단위별 평가와 마지막 합성을 수행한다. 개요 크기를 포함해 청크를 다시 나누고 실제 직렬화된 요청이 200 KiB 이내인지 확인한다. 기존 합성은 긴 응답이 200 KiB를 넘길 수 있으므로 최종 합성에 파일 경로·단위 ID와 coverage가 포함된 크기 제한 요약을 전달하고 생략을 명시한다. 개요 실패, 예산 소진, 중단과 재시도는 기존 안전 정책을 따르고 실패를 성공으로 숨기지 않는다.
5. 마지막 합성은 PR 목적과 함께 분석 가능한 입력 변경 ID에 연결된 핵심 후보와 선정 근거를 제한된 개수로 반환한다. 허용되지 않은 ID, 중복, 미분석·제외·누락 ID는 거부하며 파일 단위로 중복을 정리한다. 메인에서는 중요도 다음에 이 관련성 순서를 사용하고 근거와 함께 핵심 후보를 구분한다. 독립 규칙 후보가 상위 3개에서 빠지더라도 후보 수와 상세 진입 경로를 별도로 제공해 감추지 않는다. 이전 결과에는 새 필드가 없을 수 있으므로 기존 정렬로 안전하게 표시한다.
6. 버전·응답 스키마·캐시 키 및 저장 결과의 호환을 확인하고, 사용자 데이터와 기존 결과를 보존한다. 새 필드는 기존 `output_json`의 선택적 확장으로 취급하고, DB 스키마 변경 없이 기존 상세 및 미분석 표시를 유지한다. 작은 PR은 추가 개요 비용이 없으며 다중 청크는 정상 경로에서 기존 대비 1회 모델 호출이 늘어난다. 자동 분석은 일일 호출 한도를 적용하며 웹·CLI 수동 요청은 예외다. 재시도와 한도 초과는 별도 표시한다.
7. 현재 평가 19건은 모두 단일 청크이며 목적 판단을 검증할 제목·설명이 부족하다. 다중 청크에서 핵심 로직과 관련 설정이 떨어진 사례, 무관 문서·테스트가 많은 사례, 설명과 코드가 다른 사례, 민감 정보·누락 사례를 별도로 만들고 사람이 기준 파일과 목적을 확인한다. 정제된 동일 평가 사례·고정 모델·같은 기준으로 변경 전후를 비교한다. 사람이 확인한 핵심 파일 미포착, 잘못 높게 분류한 파일, 실제 메인 화면의 정렬을 재사용한 상위 3개 파일의 precision/recall, 목적 요약의 근거·정확성, 누락 표시, 호출 수와 시간 및 악성 지시·비밀값 처리를 함께 측정한다. 자동 규칙 후보 포착과 모델의 high 판정은 분리해 기록한다. 실제 모델·사람 검토가 없으면 정확도 향상을 주장하지 않는다.

## 영향과 미결 검토

- 분석 요청, 프롬프트와 응답 계약, 캐시 무효화, 예산과 진행 상태, 웹 파일 정렬, 평가 도구에 영향이 있다. DB 스키마 변경은 현재 예상하지 않는다.
- 정상 호출은 기존 `청크 수 + 1회`에서 다중 청크만 `청크 수 + 2회`로 늘어난다. 실제 분할 수는 개요 공간 때문에 증가할 수 있고 각 실패 재시도도 하루 예산을 사용한다. 예상 최소 호출 수가 남은 예산보다 크면 모델 호출 전 보류하되, 검사 이후 상황 변화나 재시도 때문에 중간 보류될 수 있다.
- 현재 청크 결과는 합성 전 메모리에만 있으므로 프로세스 종료 후 재시도는 앞선 호출을 반복할 수 있다. 기존 DB 스키마를 변경하지 않는 범위에서 이 한계를 사용자에게 보여주고, 이전 성공 분석을 보존한다. 별도 저장·재개를 구현한다면 그 보안·수명·복구 계약을 별도로 검토해야 한다.
- 부모 프로세스가 강제 종료됐을 때 Codex 자식의 종료 여부와 재요청 시 동시 호출 경합은 아직 확인되지 않았다. 격리된 가짜 프로세스로 재현하고 결과에 맞게 정리·차단 방식을 확정한다.
- 독립 설계 검토에서 현재 평가 자료 전체가 단일 청크이고 기존 지표가 모델 high와 규칙 후보를 구분하지 못한다는 점을 확인했다. 다중 청크 평가와 목적·파일 순위 평가를 추가한다.
- 독립 복원력 검토에서 기존 합성 요청 크기 초과와 중간 결과 유실·예산 재소모 가능성을 확인했다. 개요·청크·합성 각각 최종 바이트 크기를 제한하고, 실패 시 이전 성공 결과와 미분석 표시를 보존하는 검증이 필요하다.
- 전역 개요의 파일 간 발췌 분배, 너무 큰 단일 단위의 처리, ID 검증, 실패 시 결과 보존, 종료 후 재시도와 API 호출 제한을 독립 검토 중이다.
- 분석에 사용하는 GitHub 코드와 모델 전송은 이미 허용한 범위에서만 처리한다. 개인 PR이나 실제 서비스 데이터로 평가하지 않고 격리된 평가 자료를 사용한다.

## 상태

- 사용자가 제안된 방향의 구현과 자동·수동 예산 정책을 승인했다. 자동 검증 및 실제 모델 품질 평가가 완료될 때까지 완료 게이트는 미충족이다.

## 구현 검토와 미완료 사항 (2026-11-03)

- 독립 구현 검토: 최초 🔴 1건, 🟠 2건. 상세의 개요·합성 생략 수치 표시와 메인 파일 선택 함수 공유를 반영했고 관련 테스트를 추가했다. 민감 입력·모델 출력 정제 테스트 및 평가 지표 테스트도 보강했다.
- 부모 프로세스를 강제 종료한 뒤 자식 프로세스가 살아 있는 동안 별도 프로세스가 flock을 다시 획득할 수 있음을 임시 디렉터리와 가짜 자식 프로세스로 재현했다. 실제 사용자의 프로세스는 건드리지 않았다. 중복 호출 방지 대책은 미구현이며 G4는 미충족이다.
- 격리 홈과 합성 `fx-multichunk`를 사용한 실제 모델 1회: gpt-6.1-terra, Codex CLI 0.166.0, overview 1회·chunk 3회·synthesis 1회, 123개 분석, 지정 파일 3개가 화면 상위 3개. 비교군·반복·사람의 정답 검토가 없어 정확도 개선 근거가 아니다. G8은 미충족이며 출시 검사도 사람 확인 누락으로 차단된다.
- `skim analyze`를 기존 외부 스케줄러에서 호출 중이라면 `skim analyze --automatic`으로 바꿔야 자동 예산이 적용된다. 내부 주기 실행은 자동 예산을 유지한다.

## 중단 복구 구현 결정

- 모델 호출의 감독 프로세스가 `analysis.lock` 파일 디스크립터를 승계하고, Codex를 별도 프로세스 그룹으로 실행한다. 부모가 강제 종료돼도 감독이 모델 종료와 그룹 정리를 마칠 때까지 잠금을 보유한다. 잠금 해제는 명시적 `LOCK_UN`이 아닌 마지막 디스크립터 close로 한다.
- 감독은 모델 실행 전 미완료 표식을 원자 생성하고, 프로세스 그룹 종료가 확인된 뒤에만 제거한다. 감독 자체가 비정상 종료되어 생존 여부가 불명확하면 표식을 남겨 이후 모델 호출을 차단한다. PID만 보고 자동으로 표식을 지우지 않는다.
- CLI 격리 probe도 같은 모델 호출 경계와 잠금을 사용한다. 웹 작업의 기존 재시작 복구는 중단을 표시하고 자동 재호출하지 않는다. 잠금 대기 중에는 진행 단계에 대기를 표시한다. 분석 중간 결과는 재사용하지 않으며 자동 호출 예산은 이미 예약한 호출을 보존한다.
- 검증은 임시 홈에서 가짜 모델이 상속 FD를 모두 닫은 뒤 부모를 SIGKILL해도 잠금이 유지되는지, 모델 종료 후 해제되는지 확인한다. 감독 종료, 타임아웃, 표식 차단, 기존 작업 상태 및 예산도 격리 환경에서 검증한다. 이 방식은 운영체제 프로세스 그룹에서 스스로 이탈하는 임의 후손까지 추적하지는 못한다.

### 중단 복구 검증 결과

- 격리된 실제 프로세스 시험에서 모델이 상속 FD를 모두 닫아도 부모 SIGKILL 뒤 잠금이 유지되고 모델 종료 뒤 해제됨을 확인했다. 감독 SIGKILL 뒤 남는 표식은 재호출 및 추가 자동 예산 예약을 차단한다. 정상 실행, 타임아웃 및 웹 재시작 시 중단 상태도 가짜 실행으로 확인했다.
- macOS에서 종료된 그룹 리더에 killpg가 EPERM을 돌려주는 경우를 정상 호출 시험으로 확인해, 리더를 회수한 뒤 그룹 소멸을 확인하도록 처리했다. 타임아웃 중 권한 오류나 그룹 소멸 미확인 시에는 표식을 남긴다.
- 독립 구현 검토는 🟠 1건(상태 점검이 남은 표식을 정상으로 표시)을 지적했다. 잠금 대기 중인 정상 호출과 불확실한 표식을 구분하여 후자를 점검 실패로 보고하고, 실제 doctor.run 회귀 테스트를 추가했다. 검토자의 후속 독립 재검토는 워크스페이스 사용 한도 도달로 실행되지 않았다. 이후 추가한 macOS 정상 종료 처리도 독립 재검토되지 않았다.
- 전체 테스트 408개 통과. `knack gate reverify`에서 자동 8개 통과, 사람 검토와 반복 A/B가 필요한 기존 G8은 미충족이다. 원격 모델 서비스 내부의 정확히 한 번 실행은 이 로컬 잠금으로 보장하지 않는다.
