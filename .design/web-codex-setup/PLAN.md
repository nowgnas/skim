# 웹에서 Codex 분석 준비와 격리 검증

> 상태: 완료 · 기준: 현재 main · 규모: 표준 · 고위험: 아니오

## 1. 요구사항
- 상태와 작업 페이지에서 Codex 분석용 홈을 초기화하고 실제 격리 검증을 실행할 수 있다.
- 각 단계의 진행, 성공, 실패 및 다음 조치를 웹에서 확인할 수 있다.
- 사용자가 명시적으로 요청할 때만 실제 모델 검증을 실행한다.

## 2. 정책 점검
- ✅ 일반 상태 점검은 기존처럼 캐시 확인만 한다. 실제 모델 호출이 있는 검증은 별도 버튼과 설명을 제공한다.
- ✅ 초기화는 `init_home(reset=False)`를 사용해 원본 인증 내용은 읽거나 출력하지 않고 링크만 만든다. 기존 파일을 삭제하거나 덮어쓰는 `--reset`은 웹에서 자동 실행하지 않는다.
- ✅ 현재 서버의 `CODEX_HOME`, 모델 설정, 기존 격리·인증 검사와 단일 작업 큐를 사용한다.
- ⚠️ 검증은 저장소 코드 없이 모델 서비스에 테스트 입력을 보내고 호출 비용 또는 사용량이 발생할 수 있다. 버튼 옆에 이 사실을 표시한다.
- ✅ 서버 재시작 시 실행 중 검증은 기존 작업 복구 규칙대로 실패로 표시하고 자동으로 모델을 재호출하지 않는다.
- ⚠️ 이미 다른 상태 점검 작업이 대기·실행 중이면 새 요청이 무시되지 않도록 현재 작업을 보여주고 완료 후 다시 요청하도록 안내한다.

## 3. 열린 질문
- 없음. 위 동작과 검증 계획에 대한 승인 필요.

## 4. 코드 맥락
- `lib/skim/analyze/codex.py`: 전용 홈 초기화와 probe 보안 검증.
- `lib/skim/doctor.py`: 일반 상태 점검과 probe 실행. 현재 웹은 probe=False.
- `lib/skim/jobs.py`, `web_jobs.py`: 단일 워커·상태 페이지·작업 표시.
- `lib/skim/db.py`: 작업 종류 제약. 가능하면 기존 doctor 작업과 검증된 params로 구현해 마이그레이션을 피한다.
- `tests/test_web_jobs.py`, `tests/test_codex.py`: 안전 경계 및 작업 테스트.

## 5. 설계
- 상태 페이지에 **분석 준비 초기화**와 **격리 검증 실행**을 추가하고, 기존 상태 점검과 차이를 설명한다.
- 작업 요청은 기존 POST 인증·CSRF·속도 제한·오프라인 차단과 백그라운드 큐를 통과한다. `doctor` 작업의 제한된 action 값으로 점검/초기화/probe를 구분한다.
- 초기화는 기존 안전 검사와 분석 잠금을 사용하며, 비어 있지 않은 전용 홈이나 소유·경로 문제가 있으면 실패 안내 후 기존 내용을 보존한다. 초기화 이후 일반 상태 점검으로 결과를 보여준다.
- probe는 기존 `doctor.run(probe=True)`로 격리 검증하고 성공 캐시를 남긴다. 버튼 실행 전 실제 모델 서비스 호출을 화면에 명시한다.
- 기존 처리 중 작업과 다른 요청이 충돌하면 접수된 것처럼 표시하지 않고 대기 안내를 제공한다. 검증과 분석은 기존 분석 잠금으로 직렬화한다.
- DB 스키마와 환경 변수 계약은 변경하지 않는다.

## 6. 검증 계획
- 최초 초기화, 기존 홈 보존, 경로·소유·권한 오류, 실제 호출을 모의한 probe 성공·실패와 캐시 생성, 중복·충돌 요청, 재시작, 오프라인·인증·CSRF 검사를 검증한다.
- 관련 테스트와 전체 unittest, 독립 리뷰를 실행한다. 실제 계정으로 모델을 호출하지 않는다.

## 8. 결과
- 상태 화면에 초기화와 명시적 격리 검증을 추가했다. 기존 홈은 삭제하지 않으며, 초기화 뒤 일반 상태 점검을 표시한다.
- 웹 초기화·probe는 기존 단일 큐와 분석 잠금을 사용한다. 다른 종류의 doctor 작업이 활성 상태이면 새 요청을 409로 안내한다.
- `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -q`: 261개 통과. 독립 리뷰 중 초기화 후 일반 점검 누락을 수정하고 재검증했다.
- 실제 계정으로 초기화하거나 모델을 호출하지 않았다. 브라우저 수동 검증은 수행하지 않았다.
