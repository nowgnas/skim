# 목록 검색·페이징과 의도 분석 재시도

> 상태: 승인됨 · 기준 커밋: `4bae6e4` · 규모: 표준

## 1. 요구사항
- PR, 저장소와 분석 정책 등 항목이 많아질 수 있는 목록을 검색하고 페이지별로 탐색한다.
- 의도가 분석되지 않은 PR은 기존 안전 정책을 지키며 다시 분석을 요청할 수 있다.
- 검색·필터와 페이지 이동을 함께 사용하고, 검색 결과 없음과 범위를 벗어난 페이지를 처리한다.

## 2. 정책 점검
- ✅ 분석 동의, 일일 호출 예산, 격리 검증 및 작업 직렬화는 기존 경로를 사용한다.
- ⚠️ 페이지 크기는 20개로 가정하고, 검색은 각 목록에 표시되는 식별 정보를 대상으로 대소문자를 구분하지 않는다.
- ⚠️ 자동 재시도는 추가하지 않고 사용자가 PR 상세 화면에서 요청한다. 분석할 수 있는 변경 단위가 없으면 그 이유를 표시한다.

## 3. 열린 질문
- 없음. 위 가정과 범위에 대한 설계 승인 필요.

## 4. 코드 맥락
- `lib/skim/web.py`: PR 목록의 기존 필터, PR 상세와 GET 쿼리 처리.
- `lib/skim/web_settings.py`: 연결된 저장소, 조회 저장소, 저장소·조직 정책 목록.
- `lib/skim/web_jobs.py`: 기존 PR 분석 요청과 안전 검사.
- `lib/skim/analyze/__init__.py`: 부분 결과도 캐시에 포함되므로 의도가 없는 결과가 재사용될 수 있다.
- `tests/test_web.py`, `tests/test_web_settings.py`, `tests/test_web_jobs.py`, `tests/test_analyze.py`: 관련 동작 검증.

## 5. 설계
- 기존 서버 렌더링과 표준 라이브러리를 활용해 목록별 검색어와 페이지를 GET 쿼리로 유지한다. PR 변경 단위 목록도 검색·페이징하며 전체 diff 보기 동작은 유지한다.
- 목록별 독립 파라미터로 같은 화면의 다른 검색 상태를 보존한다. 검색 조건 변경 시 유효 범위의 페이지를 선택하고 빈 결과를 안내한다.
- 의도가 없는 캐시 결과는 성공한 분석 결과로 재사용하지 않는다. PR 상세의 기존 분석 요청에 재시도 안내를 제공한다. 분석 가능한 단위가 없으면 기존 결과를 반복 호출하지 않도록 원인을 알린다.
- DB 스키마와 기존 분석 동의, 예산, 잠금, 수집 정책은 유지한다.

## 6. 검증 계획
- 목록 경계, 검색, 빈 결과, 필터와 쿼리 유지, 독립 목록의 페이지 이동을 확인한다.
- 의도 없는 결과의 재요청, 성공 캐시 재사용, 분석 불가능한 입력 및 예산·동의 제한을 확인한다.
- 관련 테스트와 프로젝트 CI의 `python -m unittest discover -s tests -v`를 실행한다.

## 9. 결과
- PR, 저장소, 정책, 변경 단위 목록에 검색과 20개 단위 페이지 이동을 적용했다.
- 의도가 없는 캐시는 특정 스냅샷의 수동 분석에서만 재시도한다. 분석 가능한 단위가 없으면 사유 확인을 안내한다.
- 검증: `python3 -m unittest discover -s tests -q` 전체 테스트, `git diff --check`.
- 독립 리뷰: impl-reviewer, 🔴 0, 🟠 1(폼과 실제 화면 페이지 이동 테스트 보강), 잠재 🔴/🟠 0.
- 트랜잭션, 동의, 분석 잠금 및 예산 규칙은 기존 경로를 유지한다.
