# skim 사용자 설치와 업데이트

> 상태: 승인됨 · 기준 커밋: `a5a28d1` · 규모: 표준 · 고위험: 예 — 실행 중 작업, 업데이트 전환, 로컬 데이터 호환성

## 1. 요구사항
- 처음 사용하는 사람은 macOS에서 프로그램을 설치하고, 이후 터미널과 웹 설정에서 정식 버전 업데이트를 확인·실행한다.
- GitHub의 공개된 정식 릴리스만 사용한다. 초안·사전 공개 버전과 개발 브랜치는 자동 설치하지 않는다.
- 기존 설정·인증·분석 및 수집 기록을 보존하고 업데이트 중 진행 중인 작업을 임의로 중단하지 않는다.
- 현재 정식 릴리스가 없으므로 릴리스 없음과 네트워크 실패를 구분해 안내한다. 릴리스 발행은 이 요청에 포함되지 않는다.

## 2. 정책 점검
- ✅ 업데이트 경로는 사용자 선택에 따라 웹 설정과 터미널 양쪽이다.
- ✅ 배포 채널은 정식 릴리스만이다. 현재 태그·GitHub 릴리스는 없다. `nowgnas/skim`은 비공개 저장소이며 설치자는 `gh` 로그인과 저장소 읽기 권한을 보유한다는 사용자 답변을 받았다.
- ✅ 출시 체크리스트 `docs/release-checklist.md`의 평가 게이트를 유지한다. 테스트용 태그·릴리스를 실제 GitHub에 만들지 않는다.
- ✅ GitHub의 릴리스 정보와 다운로드는 읽기 전용이며 임의 URL, 압축 해제 경로, 크기 및 검증 실패를 확인한다.
- ✅ 사용자 저장소의 미커밋 코드와 다른 설치의 앱·파일은 덮어쓰지 않는다. 기존 설치를 자동으로 삭제·이전하지 않는다.
- ⚠️ 업데이트는 실행 코드와 서버 프로세스를 교체한다. 진행 중인 작업이 끝나기 전에는 전환하지 않으며, 전환과 재시작이 실패하면 상태를 표시하고 기존 실행본 및 데이터 복구 경로를 유지한다.

## 3. 코드 맥락
- `setup.sh`, `lib/skim/setup.py`: 현재 저장소에 링크를 만드는 설치만 지원.
- `lib/skim/macos_bundle.py`: 앱·LaunchAgent 설치, 환경·소유권·서버 식별 검사.
- `lib/skim/web.py`, `web_settings.py`, `web_jobs.py`, `jobs.py`: 인증된 설정 UI, 작업 큐, 단일 서버와 수집·분석 워커.
- `lib/skim/config.py`, `db.py`: 사용자 데이터 경로 및 DB 마이그레이션.
- `docs/release-checklist.md`: 정식 출시를 위한 사전 평가 조건.

## 4. 설계
- 최초 설치와 업데이트는 프로그램 코드 전용 사용자 경로를 사용하며 데이터 경로와 분리한다. 설치 시 기존 경로·소유권을 확인하고 사용자 파일을 덮어쓰지 않는다.
- 신뢰 출처는 `nowgnas/skim` GitHub 정식 릴리스로 고정한다. 인증된 GitHub API로 릴리스 목록을 조회해 빈 목록과 인증·권한 실패를 구분한다. 정식 태그의 비교 규칙과 macOS 배포 파일·체크섬 이름은 구현 전 명시하고, 초안·사전 공개·최신 태그 부재는 별도로 처리한다. 다운로드와 압축 해제는 임시 위치에서 수행하고 용량, 경로 탈출·링크 및 무결성 검사를 거친 후에만 적용한다. 체크섬은 다운로드 오류 감지용이며 서명 검증을 대체한다고 주장하지 않는다.
- 릴리스 자산 계약: `vMAJOR.MINOR.PATCH` 정식 태그와 같은 버전의 manifest, `skim-macos.tar.gz`, `SHA256SUMS`, 최초 설치용 스크립트. manifest·태그·아카이브 버전이 다르거나 자산이 하나라도 없으면 거부한다. 설치 bootstrap은 `nowgnas/skim` 정식 릴리스에서 내려받은 스크립트를 한 번 실행하는 방식이다. 현재 릴리스가 없으므로 게시 전에는 설치가 불가능함을 안내한다.
- 웹과 CLI는 같은 업데이트 엔진을 사용한다. 웹의 업데이트 확인·실행은 기존 인증·CSRF를 적용하고, 현재 버전·대상 버전·작업 상태·결과를 보여 준다. 연결된 동작이 완료되기 전에 성공으로 표시하지 않는다.
- 서버가 작업 중이면 대기 또는 재시도를 명확히 표시한다. 웹 큐만이 아니라 CLI 수집·분석과 설정 쓰기 등 모든 변경 진입점이 공유하는 유지보수 경계를 DB 접근 전에 적용해야 한다. 실행 중 작업을 소진한 뒤 관리된 서버만 전환하며 수동 서버나 다른 설치는 강제 종료하지 않는다. 경합·종료·재진입에서도 중복 적용되지 않아야 한다.
- 프로세스 종료 뒤에도 유지되는 별도 업데이트 관리자가 전환과 재시작을 책임진다. 데이터 경로에 원자적으로 기록한 업데이트 journal로 준비·백업·전환·재시작·완료를 구분하고, 재진입 시 마지막 단계를 복구한다. 기존 `jobs.recover`가 전환 작업을 일반 실패로 처리하지 않도록 책임을 분리한다.
- 요청을 확정 대상 버전·자산 해시·설치 ID에 묶고, 중복 요청은 같은 작업으로 합친다. 네트워크 작업에는 크기·시간 제한을 둔다. 독립 관리자가 `prepared → quiesced → backup → switched → ready → committed`를 내구성 있게 기록한다. 재시작 후 reconcile은 기록과 실제 파일을 대조해 마지막 단계를 멱등하게 재개하거나 명시적으로 실패시킨다.
- 영구 launcher 또는 `skim update` 시작 시 미완료 journal을 발견하면 복구 관리자를 다시 실행한다. 모든 일반 진입점은 잠금 확보 후 journal을 읽고 `committed` 전 DB 접근을 차단한다. readiness 검사는 해당 업데이트 ID에 한정한다. `committed`의 내구성 있는 기록 후에만 일반 쓰기를 열며, 완료 후 재진입은 백업 복원 없이 쓰기 개방만 마무리한다.
- 기존 버전은 새 유지보수 잠금에 참여하지 않으므로 최초 전환은 기존 수동 서버와 별도 CLI 작업을 사용자가 모두 종료한 뒤에만 진행한다. 자동으로 정리하거나 활성 작업을 강제 종료하지 않는다. 새 버전부터 웹·CLI·주기 수집의 DB 연결과 변경 작업 전체가 공통 장벽에 참여하고 잠금 순서를 고정한다.
- 기존 macOS 앱과 LaunchAgent는 `realpath`된 실행 경로를 저장하므로 단순 심볼릭 링크 전환만으로는 갱신되지 않는다. 관리된 설치의 안정적인 진입점과 앱 마커·LaunchAgent 경로 계약을 함께 설계하고 갱신 결과를 검증한다. 기존 개발 체크아웃은 자동 변환하지 않고 안내한다.
- 사용자 설치 ID와 버전 payload의 실제 경로를 분리한다. 앱과 LaunchAgent는 사용자 전용 영구 launcher를 가리키고 launcher는 검증된 현재 버전을 실행한다. 각 프로세스는 시작 시 확정한 불변 버전 경로에서만 코드를 불러온다. 기존 다른 설치의 앱 이름·LaunchAgent label 충돌은 변경하지 않고 중단한다. LaunchAgent 설정은 같은 디렉터리에서 완성·검증한 다음 원자적으로 게시한다.
- DB 스키마 변경은 이번 기능에서 추가하지 않는다. 향후 릴리스에 대비해 SQLite 백업 API로 WAL을 포함한 일관된 백업을 만든다. 마이그레이션 실패나 재시작 실패 시 새 버전의 사용자 쓰기를 열기 전에 복구를 결정한다. 새 버전이 이미 데이터를 쓴 뒤에는 기존 백업을 자동 덮어쓰지 않으며, 구 버전과 새 스키마의 호환성을 확인하지 못하면 자동 롤백하지 않는다.
- 성공은 새 서버의 버전, DB 초기화와 워커 준비가 모두 확인되고 journal이 committed로 기록된 상태다. 전환 직후, DB 마이그레이션 직후, 준비 완료 직후에 종료되더라도 각 상태를 복구할 수 있어야 한다. DB 복원은 모든 연결을 닫고 WAL/SHM을 안전하게 처리한 뒤에만 수행한다.
- 버전은 `vMAJOR.MINOR.PATCH`의 정수 세 항목으로 비교한다. 같은 버전의 해시가 달라지면 거부하며 자동 다운그레이드는 지원하지 않는다. 다운로드와 리다이렉트는 HTTPS의 `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`만 허용하고 리다이렉트에 인증 헤더를 전달하지 않는다. 허용 범위 밖이면 안전하게 실패한다.
- 배포물 생성 전에 `scripts/check_release.py` 성공을 필수로 확인하고, 실패하면 배포물과 체크섬을 생성하지 않는다. 생성·게시 방법은 저장소에 제공하되 실제 릴리스 발행은 하지 않는다.

## 5. 영향과 검증 계획
- 주요 영향: 설치 경로, CLI, 설정 화면, 업데이트 워커·재시작 및 LaunchAgent, 사용 중인 작업, DB 백업·복구.
- 확인 대상: 미출시·최신·업데이트 가능, 손상된 다운로드·경로 탈출, 부분 설치·재시도, 동시 요청, 작업 중 대기, 비정상 종료, 기존 앱·개발 체크아웃과 다른 설치, 재시작 실패·데이터 복구.
- 고위험 검증은 격리된 임시 설치·가짜 릴리스·로컬 SQLite 및 가짜 프로세스로 정상 전환, 실패·경합·복구를 확인한다. 이 테스트의 추가·실행은 사용자가 구현과 검증을 함께 요청한 경우에만 수행한다. 실행하지 못한 항목은 완료 게이트 미충족으로 남긴다.
- 서버 실행이 `guard-prod-ops`에 차단되면 우회하지 않는다. 실제 사용자 서버·릴리스 상태를 바꾸는 작업은 실행하지 않는다.

## 8. 결과
- 릴리스 조회·자산 검증, 버전 저장소, 업데이트 journal과 SQLite 백업·복구의 기반을 작성했다. 비공개 저장소의 `gh` 인증을 사용한다.
- 독립 리뷰에서 tar 확장 헤더의 압축 해제 크기 제한 우회를 발견해 전체 gzip 해제 크기를 제한하고 회귀 테스트를 추가했다.
- 복원력 리뷰에서 발견한 프로그램 경로와 데이터 경로 사이의 잠금 충돌 및 버전 게시 직후 재시도 문제를 보완했다. 전환 전 취소와 완료된 journal 요청의 중복 제거를 추가했다. 다운로드 전체 시간 제한과 관리자에서 실제 현재 버전 확인은 통합 시 해결하고 검증해야 한다.
- 재검토에서 최초 게시와 재시도의 파일 개수 제한 차이를 발견해 두 경로에 동일한 검사를 적용했다. launcher의 bytecode 생성 방지와 데이터 경로 확인은 미구현이다.
- 최초 설치 bootstrap, 영구 launcher, CLI·웹 연결, 작업 대기 및 서버 재시작·readiness 확인은 아직 구현되지 않았다. 이 기반 코드는 기존 실행 경로에 연결되지 않으며 사용자용 업데이트가 아니다.
- 완료 게이트 8개는 증거 미기록 상태다. 실제 정식 릴리스도 없어 실제 설치 및 업데이트를 검증하지 않았다.
- 이 기기의 LaunchAgent는 `/Users/sangwolee/skim/bin/skim` 개발 체크아웃을 가리킨다. 기존 설치는 그대로 유지하며, 릴리스 설치 전환 전에 안정적인 launcher 경로와 작업 대기 방식이 필요하다.
- `skim update`와 `skim update --check`의 정식 릴리스 조회를 연결했다. 아직 자동 적용은 구현되지 않았으며, 릴리스가 있을 때 적용 성공을 표시하지 않고 종료한다.

## 9. 설치 리뷰 수정 1회차

- 사용자 요청에 따라 macOS와 Linux에 같은 순수 Python 아카이브를 설치한다. 기존 자산 이름 `skim-macos.tar.gz`와 manifest 계약은 유지한다. Linux의 `skim app`은 안내만 제공한다.
- 저장소 설치 스크립트는 전체 본문을 받은 뒤 main을 실행한다. Python 3.11 이상 실행 파일을 버전 이름으로도 찾고 모든 검증 Python을 격리 모드로 실행한다. 다운로드 전에 gh 인증과 auth token 지원, Codex 최소 안정 버전과 필수 격리 플래그를 확인한다.
- Linux에서 필요한 도구가 없으면 배포판별 Python 패키지 조회 및 수동 설치 안내를 제공한다. 구버전 Python, gh, Node.js를 자동 설치하지 않는다.
- 영구 launcher는 실행 시 Python을 선택하고 payload import 전에 소유자, 권한, 링크 및 데이터 경로 분리를 검사한다. 사용자 도구 경로의 Codex를 우선 사용하되 명시적 SKIM_CODEX_BIN을 보존한다.
- 정식 설치본의 macOS 앱 연결은 아직 완성되지 않았다. 버전 경로를 앱에 고정하지 않도록 앱 설치와 제거를 차단하고 터미널 실행을 안내한다. 개발 설치의 소유 마커 검사는 유지한다.
- 일반 예외와 KeyboardInterrupt는 해당 실행이 만든 프로그램 디렉터리를 정리하여 재시도할 수 있다. SIGKILL이나 전원 중단으로 남은 설치는 자동 삭제하지 않는다. 기존 파일 및 경합 중 생성된 다른 launcher는 보존한다.
- 이번 수정은 업데이트 적용, 관리자 복구, readiness 및 앱 연결 완료를 의미하지 않는다. G2, G3, G5, G6, G8의 전체 완료 판정은 계속 보류한다. 실제 배포판 설치, macOS 기본 bash 3.2 실행 및 실제 GitHub 다운로드는 수행하지 않는다.
- 검증 결과: `PYTHONPATH=lib python3 -m unittest discover -s tests` 전체 519개 통과. 설치 스크립트 회귀 테스트 15개와 설치 및 업데이트 테스트 55개를 포함한다. `bash -n scripts/install.sh`와 `git diff --check`도 통과했다. 테스트는 가짜 도구, mock 및 임시 디렉터리를 사용했으며 실제 릴리스 생성과 네트워크 설치는 수행하지 않았다.

## 10. 설치 재리뷰 수정 2회차

- 재리뷰 1, 3, 4, 5, 6, 7번을 수정했다. rebase는 이번 작업에서 수행하지 않았다.
- 설치 경로 검사와 영구 launcher는 현재 사용자 이름의 전용 기본 그룹이고 다른 기본 및 보조 멤버가 없을 때만 그룹 쓰기를 허용한다. 공유 그룹이면 `chmod g-w` 해결 방법을 안내하며 기존 권한은 자동 변경하지 않는다. macOS 앱과 제거의 기존 소유 마커 검사는 유지한다.
- launcher의 `/tmp` 예외를 제거했다. launcher 실행 테스트는 안전한 상위 경로의 임시 디렉터리를 사용하며 공유 임시 경로와 sticky 디렉터리도 별도로 거부하는지 검사한다.
- gh는 `gh help auth`의 하위 명령 목록에서 `token` 지원을 확인한다. Codex 부재, 구버전 및 필수 플래그 미지원은 분석 준비 경고와 설치 안내를 출력하며 skim 설치를 막지 않는다.
- 릴리스 API 인자의 glob 확장을 막고 README에 bash의 `~/.bashrc` 안내를 추가했다.
- 검증은 mock, 가짜 CLI 및 임시 디렉터리만 사용한다. 실제 GitHub 릴리스와 태그 생성, 네트워크 설치 및 커밋은 수행하지 않는다. 업데이트 적용, 복구 관리자, readiness 및 정식 설치본 앱 연결의 기존 미완료 게이트는 이번 수정으로 완료되지 않는다.
- 검증 결과: `python3 -m unittest discover -s tests` 전체 528개 통과. `bash -n scripts/install.sh`와 `git diff --check`도 통과했다. 실제 Ubuntu 기본 환경과 macOS 기본 bash 3.2에서의 실행은 검증하지 않았다.
