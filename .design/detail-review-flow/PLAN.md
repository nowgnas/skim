# PR 상세 검토 흐름 개선

## 요청과 승인된 방향

PR 목적과 실제 변경을 이해하고, 핵심 파일부터 diff를 검토하며, 분석의 한계와 GitHub 원문을 확인하는 흐름을 제공한다. 사용자가 기존 상세 페이지 자가 검토에서 제안한 모든 수정 방향을 승인했다.

## 구현

- PR 목적과 원본 설명, 중요한 파일과 선정 근거를 우선 표시한다. 오래된 SHA·실패·미허용 결과는 현재 결과처럼 활용하지 않는다.
- 상세 정렬은 중요도, PR 목적 관련성, 규칙 후보 순으로 메인과 일치시킨다. 미분석과 제외는 별도 검토 안내와 링크로 제공한다.
- 여러 hunk를 파일별로 묶고 파일 목록과 파일 단위 검색·페이지 이동, 내부 앵커 및 GitHub 새 탭 링크를 제공한다. 기존 unit_q 링크는 유지한다.
- diff에 이전·이후 줄 번호와 추가·삭제 전체 행 색상을 표시하고 긴 줄은 가로 스크롤로 읽는다. 모델 근거를 코드 앞에 간결하게 표시하고 내부 구분 값은 접는다.
- 제외·누락·정제·이전 SHA와 기타 부분 분석은 명확히 구분하고 해당 파일 또는 상태 조치에 연결한다. 모델·시각·수집 상세 정보는 접을 수 있다.
- 데이터베이스, 모델 호출, 분석 동의 및 기존 원본 diff 보안 경계를 바꾸지 않는다.

## 검증 계획

기존 테스트와 소비자 계약을 읽고, 격리된 가짜 PR 화면을 렌더링해 확인한다. 이번 작업에서는 별도 테스트를 추가·실행하지 않는다. 구문 검사와 diff 검사를 수행한다.

## 검토 결과

- 독립 리뷰에서 정제된 여러 줄의 잘못된 줄 번호와 범위 링크의 필터 유지 문제를 지적했다. 정제 hunk의 줄 번호를 숨기고 원문을 안내했으며, 정제 파일별 링크와 필터를 제거한 전체 파일 링크를 추가했다. 최종 링크 변경은 두 번째 리뷰 응답 직후 반영되어 독립 재검토하지 못했다.
- 격리된 예시 PR의 데스크톱 화면과 파일 목록 클릭으로 접힌 파일이 열리는 동작을 직접 확인했다. 자동 테스트는 실행하지 않았다. 기존 상세 화면의 HTML 구조에 의존하는 일부 테스트 기대값은 새 화면과 달라 갱신이 필요하다.

## 파일 전환 UX 수정

- ‘먼저 볼 파일’은 선택한 파일로 좁히지 않는다. 파일 검토 영역의 전체 목록을 유지하며 선택 파일의 diff를 표시한다.
- 한 페이지의 파일 20개에 대해 서버가 파일별 내용을 제공하고 클라이언트는 선택 내용만 전환한다. 상단 추천 클릭은 검토 영역으로 한 번 이동한다. 이후 목록에서 전환할 때 페이지를 다시 열거나 목록을 초기화하지 않는다.
- 자바스크립트가 없거나 선택 파일이 다른 페이지인 경우 서버 링크로 해당 파일이 포함된 페이지를 연다. 파일 검색, 원래 순서, 페이지 탐색은 독립적으로 작동한다. 직접 링크와 기존 unit_q 경로도 지원한다.
- 모바일은 현재 페이지의 파일 선택 드롭다운을 표시하고 데스크톱은 선택 표시와 중요도가 있는 파일 목록을 유지한다.

### 파일 전환 UX 검토

- 독립 리뷰에서 파일 선택 후 정렬 링크가 이전 파일을 가리킬 가능성과 정확한 검색어가 페이지를 되돌리는 가능성을 지적했다. 선택 시 보기 링크를 갱신하고 명시적 페이지 요청의 자동 선택을 막았으며, 독립 재검토에서 수정 경로를 확인했다.
- 임시 데이터의 데스크톱 화면에서 추천 파일 선택 후 목록 20개 유지, 다른 파일 선택 시 페이지 스크롤 유지, 정렬 변경 후 선택 파일 유지를 확인했다. 모바일 폭에서 파일 선택 드롭다운과 diff 배치를 확인했다. 브라우저 확인은 가짜 데이터만 사용했다.
- Python 구문 검사, JavaScript 구문 검사, git diff 공백 검사를 수행했다. 자동 테스트는 추가하거나 실행하지 않았다. 기존 상세 화면의 이전 HTML 구조를 기대하는 테스트는 별도 갱신이 필요하다.

## 추천 파일 제자리 펼침과 화면 너비

- 사용자가 선택한 추천 파일 카드 바로 아래에서 변경 내용을 펼친다. 페이지 이동, 선택 필터 변경, 스크롤 명령 없이 기본 HTML details로 열고 닫는다.
- 파일 패널을 공통 렌더러로 만들어 추천 파일과 아래 전체 파일 검토 영역에서 같은 정제·표시 규칙을 사용한다. 추천 파일이 현재 목록 페이지에 없어도 제자리에서 확인할 수 있다.
- 파일 목록은 파일명과 간략한 상위 폴더를 표시하고 전체 경로는 title과 접근성 이름에 보존한다. 상세 페이지의 본문 최대 너비를 1600px로 늘린다.

### 제자리 펼침 검토 결과

- 독립 리뷰 결과 🔴 0 / 🟠 0. 공통 파일 패널, 중복 ID 방지, 제외·정제 변경 보호, 전체 경로 접근성 유지 확인.
- 격리된 가짜 PR 화면에서 추천 파일을 클릭한 전후 URL과 스크롤 위치가 유지되고 카드 바로 아래 diff가 펼쳐지는 것을 확인했다. 긴 경로는 파일명과 상위 폴더로 표시되며, 데스크톱 화면은 넓어진 본문으로 확인했다.
- Python·JavaScript 구문과 git diff 공백 검사를 수행했다. 자동 테스트는 추가하거나 실행하지 않았다. 기존 상세 화면의 이전 HTML 구조 및 일부 가짜 DOM을 기대하는 테스트는 갱신이 필요하다.
