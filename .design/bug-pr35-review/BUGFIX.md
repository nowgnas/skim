# PR #35 리뷰 지적 수정

> 작성일: 2026-11-02 · 기준 커밋: `fd1186b` · 심각도: 중간 · 고위험: 아니오

## 증상 및 재현
- 분석 성공 후 격리 오류가 기록되고 복구 뒤 수동 재분석하면, 작업은 기존 성공 캐시로 완료되지만 화면은 마지막 오류 기록을 보여 준다.
- `/private/tmp/skim-pr35-reproduce.py` 실행: `initial: completed`, `failure: blocked`, `retry: completed True`, `display: blocked None`.
- 저장소·정책 변경 POST 후 고정 경로로 이동해 검색어와 페이지가 사라진다.
- 최초 분석도 재시도 안내를 보여주며, 오래된 스냅샷의 분석 결과를 현재 상태로 판단할 수 있다.
- 제목이 NULL인 PR이 있으면 목록의 문자열 결합이 실패한다.

## 원인
- `lib/skim/analyze/__init__.py:165`의 캐시 반환은 새 성공 기록을 남기지 않고, `lib/skim/web.py:128`은 최신 기록을 선택한다.
- `lib/skim/web_settings.py:195` 등의 고정 redirect에는 화면 검색 상태가 포함되지 않는다.
- `lib/skim/web_jobs.py:106`은 현재 스냅샷 여부와 최초 분석 여부를 충분히 구분하지 않는다.
- `lib/skim/web.py:222`는 NULL 허용 제목을 문자열과 결합한다.

## 수정 계획
- 수동 재분석이 성공 캐시를 사용하고 그보다 최신 결과가 실패일 때, 해당 성공 결과를 트랜잭션으로 새 분석 이력에 복원하고 연결된 분석 항목도 함께 복사한다. 기존 모델 호출 예산·격리 검사와 분석 잠금을 유지한다. 최신 결과가 이미 성공이면 중복 기록하지 않는다.
- 저장소·설정 화면 폼에 허용된 해당 화면의 검색어·페이지 상태만 담고, POST 완료 후 같은 화면으로 안전하게 되돌린다. 외부 주소는 받지 않는다.
- 최초 분석, 현재 스냅샷의 실패, 이전 스냅샷 기록을 구분하고 실제 분석 가능 여부를 단정하는 부정확한 안내는 제거한다.
- 제목 NULL을 안전하게 표시·검색한다.
- 설계 문서의 완료 상태를 실제 PR 상태에 맞춘다.

## 검증 계획
- 실패 기록 뒤 성공 캐시 재사용을 포함한 재현 테스트를 실패 확인 후 통과시킨다. 분석 항목 보존, 반복 재요청, 최신 실패 노출도 확인한다.
- 저장/연결/해제 후 화면별 검색과 페이지 보존, 잘못된 반환값 거부, 최초·이전·실패 분석 안내, NULL 제목을 검증한다.
- 관련 테스트와 전체 테스트, `git diff --check` 및 독립 리뷰를 실행한다.

## 데이터 영향
- 운영 데이터 보정이나 스키마 변경 없음. 새로운 성공 이력은 수동 재요청의 정상 결과로만 기록한다.

## 재발 방지
- 성공 → 실패 → 캐시 재사용과 폼 제출 후 상태 유지 회귀 테스트를 추가한다.
